# Переезд интерфейса на React — завершён

Работа шла в ветке `react-rewrite`. Интерфейс целиком на React: `App.tsx`
рисует `AppShell`, `src/legacyApp.js` и `src/components/LegacyShell.tsx`
удалены.

Решения, принятые до начала (не пересматривались):

1. Полный переход на React сразу, без временного моста между старым `ui{}` и
   новым хранилищем.
2. Всё на отдельной ветке; приложение могло быть нерабочим в середине.
3. Мёртвый код удаляется по ходу, каждое удаление отдельным коммитом.
4. SCSS, файл рядом с компонентом, обычные (нехешированные) имена классов.
5. Состояние — zustand, серверные данные и опрос — TanStack Query.

---

## Сделано

`npm run typecheck`, `npm test` (111 тестов) и `npm run build` проходят.

- **Инфраструктура, стили, фундамент, ui-kit, каркас** — как было описано
  раньше: Sass, zustand, TanStack Query, vitest; 19 примитивов; навигация,
  шапка, вход, уведомления.
- **Слой API** сверен с `homecloud-core/web_server.py` и `server.js`, типы
  описывают фактические ответы (см. «Починено по ходу»).
- **Экраны.** Люди (сетка, альбомы людей, карточка группы, пересборка),
  Фотографии и просмотрщик, Проверка, Обучение, Сканирование, Дубликаты,
  Настройки; панель «Подборки и фильтры».
- **Переключение.** `app/Providers.tsx` — кэш запросов, `startHashSync`,
  тема. `app/AppShell.tsx` — каркас, сессия, счётчики вкладок, все окна.
  `app/ViewOutlet.tsx` — один экран из семи. `app/usePollingStatus.ts` —
  четыре запроса с интервалом вместо `pollStatus`.
- **Стили.** В `src/styles/` остались токены, темы, база и `index.scss` с
  примитивами ui-kit. Всё остальное лежит рядом с компонентами.
- **Селекторы по id** `#lightbox`, `#folderTree`, `#reclusterButton`,
  `#collectButton`, `#resetFilters` заменены классами.
- **Удалено:** легаси-файлы, дубль клиента `src/api/client.ts`, мёртвые
  стили.

### Починено по ходу (не было в плане)

- Две разные анимации назывались `slide`; побеждала вторая, поэтому мерцание
  подгрузки галереи молча не работало.
- «Дубль» тёмной темы оказался не дублем: `@media (prefers-color-scheme: dark)`
  и `:root[data-theme="dark"]` — разные условия. Сведено в примесь.
- `npx tsc --noEmit` вообще не проходил из-за динамического импорта
  немодульного `legacyApp.js` — проверка типов была бесполезной.
- Инлайновые `style="..."` внутри `innerHTML` на проде молча срезались
  политикой безопасности `style-src 'self'`. React пишет стили через CSSOM.
- Новый слой API не совпадал с бэкендом и сломал бы приложение сразу после
  переключения: вход слал `name` вместо `login`; сессия ждала `bigfam_url`,
  а `server.js` отдаёт `bigfamUrl` и `canEdit`; альбомы слали `parent`
  вместо `parent_id`; «забыть источник» — `run` вместо `id`; карточка
  группы описывалась как `{group, faces}`, а приходит плоско; `query()`
  превращал `true` в «true», бэкенд ждёт `'1'`, и фильтры размытых, 18+ и
  скрытого не срабатывали.
- Крошки папок в просмотрщике давали «D:» и «D:\\Фото» — такие папки не
  находились. Теперь пути как у бэкенда: «D:\» и «D:\Фото».
- Смещение следующей страницы галереи считалось по показанному, а «скрывать
  18+» режет страницы на клиенте — снимки пропускались.
- Опись: цикл «поспать, дёрнуть опрос» заменён мутацией и слежением за
  `device.job`; короткая опись, прошедшая между двумя опросами, тоже
  замечается.
- Esc у окна, открытого прямо по ссылке, увёл бы со страницы: шаг назад
  делается, только если окно открыли внутри приложения (`history.state.overlay`).
- Каталог и картотека запрашивались до ответа `/api/session` и получали 401.
- `SidePanel` прятался атрибутом `hidden` — теперь условный рендер.

### Отступления от плана

- **Примитивы ui-kit подключаются из `index.scss`, а не компонентами.** Их
  классы рисует и обычная разметка (ссылка `a.button`, `span.chip`, кнопки
  инструментов в строках альбомов), и в каскаде они обязаны идти раньше
  стилей экранов. Поэтому `main.tsx` подключает `index.scss` до `App`.
- **Окно «Добавить в альбом» одно** на снимки и группы людей.

## Проверено вживую

Прод-сборка через `node server.js` с живым бэкендом на этой машине и
локальной заглушкой картотеки (см. «Как проверять»). Бэкенд был без
`PHOTO_TOKEN`, поэтому проверка только на чтение.

- Все семь экранов, панель подборок, счётчики вкладок, баннер и карточки
  устройств — с живыми данными.
- Галерея подгружает страницы, адрес копии с размером под плитку.
- Просмотрщик: открытие, лента, шторка сведений. Карточка группы: лица и
  похожие группы.
- Закрытие просмотрщика и карточки группы по `cancel` уходит назад по
  истории, адрес и заголовок восстанавливаются.
- В консоли нет `Refused to apply inline style` и неперехваченных ошибок.

## Не проверено вживую

- **Изменяющие действия** — назначение имён, объединение, альбомы, скрытие и
  удаление, запуск описи и заданий, пересборка: бэкенд был без токена.
  Формы запросов сверены с `web_server.py`.
- **Вход через настоящую картотеку.**
- **Реальная клавиша Esc.** Встроенный браузер Claude шлёт Escape с
  `keyCode: 0`, и Chrome по такому нажатию `<dialog>` не закрывает. Путь
  приложения проверен отправкой `cancel`; в обычном браузере стоит нажать Esc
  руками.
- Просмотр лиц из карточки группы, речь в видео, окно задания сканирования.

## Замечено, но не менялось

- **Обложки альбомов в панели грузятся без замыливания 18+** — так было и в
  легаси: у альбома нет оценки кадра обложки, и `photoMediaUrl` применить
  не к чему. Если это нужно, бэкенду стоит отдавать оценку обложки.

## Ловушки, о которых нельзя забыть

- **`photoMediaUrl`** закреплён таблицей-тестом. Любая правка правил блюра —
  сначала строка в таблице, потом код: ошибка здесь означает откровенный
  кадр, показанный без замыливания.
- **Атрибут `hidden` и класс `.hidden` — разные вещи.** Правило: условный
  рендер по умолчанию; класс `.hidden` — только там, где узел обязан остаться
  в DOM ради перехода; атрибут `hidden` — никогда.
- **Никакого CSS-in-JS.** `server.js` отдаёт `style-src 'self'` без
  `unsafe-inline`. `style={{}}` в React безопасен, инъекция `<style>` — нет.
- **StrictMode выполняет эффекты дважды.** У каждого эффекта должна быть
  настоящая уборка: повторный `showModal()` бросает, повторные `observe` и
  `subscribe` удваиваются.
- **Порядок стилей:** `index.scss` подключается в `main.tsx` раньше `App`.
- **Просмотр лиц не закрывается через историю** — под ним открыта карточка
  группы, шаг назад закрыл бы её.
- **`deploy.ps1` делает `npm ci`** — новая зависимость должна попадать в
  `package-lock.json` тем же коммитом.
- Карточки активных задач висят до ручного закрытия, а обычные тосты гаснут
  за пять секунд. Это просьба пользователя, а не недосмотр.

## Как проверять

```bash
npm run typecheck && npm test && npm run build
```

Прод-сборку смотреть через `node server.js`, а не через dev-сервер: только
так всплывают нарушения политики безопасности (`Refused to apply inline
style` в консоли). Для живых данных нужен бэкенд на Windows (`PHOTO_BACKEND`;
токен из `F:\services\homecloud-core\backend-token.txt` — только если нужно
проверить изменения). Без запущенной картотеки `server.js` считает
пользователем того, кого вернёт `/api/auth/me` по адресу `BIGFAM_URL`: для
проверки на чтение хватает заглушки, отвечающей на него, и cookie
`kartoteka_session` с любым значением.
